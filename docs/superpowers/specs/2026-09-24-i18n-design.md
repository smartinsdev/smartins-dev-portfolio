# Internacionalização (PT-BR / EN) — Design

- **Data:** 2026-09-24
- **Status:** aprovado na conversa, aguardando revisão desta spec
- **Branch:** `feat/i18n`

## Objetivo

Publicar o portfólio em português (PT-BR) e inglês (EN). Quem é de fora cai no
inglês sem procurar botão; quem é do Brasil cai no português. É feito agora,
enquanto o site só tem o hero, porque tirar os textos de dentro dos componentes
fica mais caro a cada seção nova.

Este é o **subprojeto 1 de 2**. O subprojeto 2 é o toggle de tema
(sistema/claro/escuro), com spec própria. O seletor de tema vai morar no mesmo
painel de preferências criado aqui.

## Decisões tomadas

| Pergunta | Decisão |
| --- | --- |
| Qual idioma na primeira visita? | Detecta pelo navegador. `/` redireciona para `/pt-br` ou `/en`. A escolha manual fica num cookie e vence a detecção. |
| Biblioteca? | Nenhuma. Dicionários próprios, seguindo o guia de i18n do Next 16 (`app/[lang]` + `next/root-params`). O objetivo também é aprender o mecanismo que o next-intl esconde. |
| Onde fica o seletor? | Num botão de preferências na navbar, que abre um painel (`popover` nativo). Igual no desktop e no celular. |
| Trocar de idioma repete a intro? | Não. A página troca de idioma no estado final, na mesma posição de rolagem. |
| Bandeiras? | Não. Só texto, cada idioma escrito no próprio idioma ("Português", "English"). |
| URLs | `/pt-br` e `/en`. |
| Âncoras das seções | `#projects`, `#about`, `#contact` nos dois idiomas. |
| Textos em inglês | Claude escreve o rascunho, Sinval revisa. |

## Fora do escopo

- Tema claro/escuro (subprojeto 2).
- Seções Projetos, Sobre e Contato e o ScrollTrigger.
- Plural, formatação de datas e números por idioma: o site não tem nada disso hoje.
- Nomes de rota traduzidos (ex.: `/en/projects` vs `/pt-br/projetos`): o site tem uma página só.

## 1. Rotas e escolha do idioma

### Idiomas

`src/i18n/locales.ts` é a fonte única:

```ts
export const locales = ["pt-br", "en"] as const;
export type Locale = (typeof locales)[number];
export const defaultLocale: Locale = "en";
export const LOCALE_COOKIE = "locale";

export const hasLocale = (value: string): value is Locale =>
  (locales as readonly string[]).includes(value);

// htmlLang vai no <html lang>, ogLocale no og:locale, name no seletor.
export const localeInfo: Record<Locale, { htmlLang: string; ogLocale: string; name: string }> = {
  "pt-br": { htmlLang: "pt-BR", ogLocale: "pt_BR", name: "Português" },
  en: { htmlLang: "en", ogLocale: "en_US", name: "English" },
};
```

O padrão é `en` porque ele só vale para quem não tem nem português nem inglês
no navegador, e essas pessoas leem inglês com mais chance.

### Proxy (`src/proxy.ts`)

`proxy.ts` é o nome do middleware no Next 16. Fica em `src/`, no mesmo nível de
`app/`.

1. Se o caminho já começa com um idioma (`/pt-br`, `/pt-br/...`, `/en`, `/en/...`),
   segue sem mexer.
2. Se não, redireciona com **307** para `/{idioma}{caminho}`, mantendo a query
   string. O idioma vem de `negotiateLocale()`:
   1. cookie `locale`, se for um idioma válido;
   2. `Accept-Language`, na ordem de preferência (peso `q`, do maior para o
      menor; empate mantém a ordem do cabeçalho). O primeiro idioma cujo código
      principal é `pt` vira `pt-br`; o primeiro cujo código é `en` vira `en`;
   3. se nada bater, `defaultLocale` (`en`).
3. O `matcher` ignora `_next` e qualquer caminho com ponto (arquivos): imagens,
   `robots.txt`, `sitemap.xml`, `manifest.webmanifest`, ícones.

307 e não 301/308: o destino depende de quem visita. Um redirecionamento
permanente ficaria guardado no navegador e prenderia a pessoa no idioma antigo.

**Custo aceito:** quem digita `smartins.dev/` paga um redirecionamento (uma ida
e volta curta, sem renderização). Links internos nunca apontam para `/`, e os
links divulgados (LinkedIn, currículo) devem usar `/pt-br` ou `/en`.

### Funções puras

- `src/i18n/negotiate-locale.ts`:
  `negotiateLocale({ cookie, acceptLanguage }: { cookie?: string; acceptLanguage?: string | null }): Locale`.
- `src/i18n/localize-path.ts`:
  - `pathLocale(pathname): Locale | undefined`: o idioma no começo do caminho, se houver.
  - `localizePath(pathname, locale): string`: troca ou acrescenta o prefixo.
    `/pt-br` → `/en`, `/pt-br/x` → `/en/x`, `/x` → `/en/x`, `/` → `/en`.

Essas duas e `locales.ts` são testadas com `node --test` (seção 5). Por isso:

- importam umas às outras com a extensão `.ts` (`./locales.ts`), que o Node exige;
- não usam o alias `@/`, que o Node não entende;
- o `tsconfig.json` ganha `"allowImportingTsExtensions": true` (permitido
  porque o projeto já tem `noEmit`).

Cada um desses arquivos tem um comentário curto explicando o motivo.

### Pastas de `app/`

```
src/app/
├── [lang]/
│   ├── layout.tsx            # layout raiz: <html lang>, metadados, generateStaticParams
│   ├── page.tsx              # home
│   ├── not-found.tsx         # 404 traduzido
│   ├── error.tsx             # erro traduzido (client)
│   ├── opengraph-image.tsx   # uma imagem por idioma
│   └── [...rest]/page.tsx    # qualquer URL inexistente → notFound()
├── global-error.tsx          # fica fora: substitui o layout raiz
├── globals.css
├── robots.ts, sitemap.ts, manifest.ts
└── favicon.ico, apple-icon.png
```

- `layout.tsx` sai de `app/` e vai para `app/[lang]/`. O `not-found.tsx`,
  `error.tsx` e `page.tsx` também.
- `generateStaticParams` no layout devolve os dois idiomas: `/pt-br` e `/en`
  são geradas no build como páginas estáticas.
- O layout valida o parâmetro com `hasLocale` e chama `notFound()` se não for
  válido (como no guia do Next). Com o proxy na frente, isso só acontece em
  casos raros (ex.: `/foo.png`, que o proxy ignora por ter ponto).
- `[...rest]/page.tsx` só chama `notFound()`. É o que faz `/en/xyz` mostrar o
  `not-found.tsx` traduzido, dentro do layout do idioma. `global-not-found`
  resolveria o mesmo problema, mas ainda é experimental.
- **Não** usar `dynamicParams = false` no layout: essa opção é herdada pelas
  rotas filhas e faria o `[...rest]` devolver o 404 genérico do Next.

### Trocar de idioma não recarrega a página

`/pt-br` e `/en` usam o mesmo arquivo de layout raiz. O Next só faz
recarregamento completo ao passar para **outro arquivo** de layout raiz, então
a troca é navegação no cliente. Isso permite a troca sem intro (seção 3).

## 2. Textos, dicionários e SEO

### Dicionários

```
src/i18n/
├── dictionaries/
│   ├── pt-br.ts
│   └── en.ts
├── get-dictionary.ts
└── error-texts.ts
```

Formato, agrupado por onde o texto aparece:

```ts
// src/i18n/dictionaries/pt-br.ts
export const ptBr = {
  meta: {
    title: "Portfólio",
    description: "Desenvolvedor Full Stack. Portfólio de Sinval Martins.",
  },
  nav: { label: "Principal", projects: "Projetos", about: "Sobre", contact: "Contato" },
  preferences: { open: "Preferências", title: "Preferências", language: "Idioma" },
  hero: {
    role: "Desenvolvedor Full Stack",
    tagline: ["Disponível para", "novos projetos"],
    cta: "Ver projetos",
    newTab: "(abre em nova aba)",
  },
  notFound: {
    title: "Página não encontrada",
    description: "O endereço pode ter mudado ou nunca ter existido.",
    back: "Voltar para o início",
  },
};

export type Dictionary = typeof ptBr;

// src/i18n/dictionaries/en.ts
export const en: Dictionary = { … };
```

- `ptBr` **sem** `as const`: assim `Dictionary` tem `string` nos valores, e o
  `en` pode ter textos diferentes com as mesmas chaves. Chave faltando ou
  sobrando no `en` é erro de TypeScript (barra o `pnpm build`).
- As chaves exatas podem mudar na implementação; a regra é: todo texto visível,
  `aria-label` e `sr-only` sai dos componentes.

`src/i18n/get-dictionary.ts` (só servidor):

- `getLocale(): Promise<Locale>`: lê `lang()` de `next/root-params`, valida
  com `hasLocale`, chama `notFound()` se inválido.
- `getDictionary(): Promise<Dictionary>`: `getLocale()` + o dicionário.

Qualquer server component chama `getDictionary()` sem receber o idioma por
props. `next/root-params` já quebra o build se for importado num client
component, então não precisa de `server-only`.

### O que muda em `src/data/site.ts`

Fica só o que é igual nos dois idiomas:

- `name` ("Sinval Martins");
- `socials` (GitHub e LinkedIn: nomes próprios e URLs);
- os ids das seções: `projects`, `about`, `contact`.

`role`, `tagline`, `cta.label` e os rótulos da `nav` vão para os dicionários.

### Componentes que passam a ler o dicionário

| Componente | O que muda |
| --- | --- |
| `layout/navbar.tsx` | vira `async`; rótulos e `aria-label` do dicionário; logo aponta para `/{idioma}`; ganha o `<PreferencesMenu />` |
| `hero/hero-title.tsx` | `role` do dicionário |
| `hero/hero-info.tsx` | `tagline`, `cta`, `newTab` do dicionário; CTA aponta para `#projects` |
| `app/[lang]/not-found.tsx` | textos do dicionário; "voltar" aponta para `/{idioma}` |
| `status/error-screen.tsx` | textos de `error-texts.ts`; "voltar" aponta para `/{idioma}` |

### SEO e compartilhamento

`generateMetadata` no `app/[lang]/layout.tsx`:

- `title`: `Sinval Martins — Portfólio` / `Sinval Martins — Portfolio`, com o
  mesmo `template` de hoje;
- `description` do dicionário;
- `openGraph.locale` = `localeInfo[lang].ogLocale` e `alternateLocale` = o do
  outro idioma;
- `alternates.canonical` = `/{lang}`;
- `alternates.languages` = `{ "pt-BR": "/pt-br", en: "/en", "x-default": "/" }`.

O `alternates.canonical` que hoje está em `page.tsx` sai de lá.

**Imagem de compartilhamento:** `app/[lang]/opengraph-image.tsx` recebe
`params` (não `lang()`: `next/root-params` não roda em rotas de imagem) e
desenha o cargo no idioma. O texto alternativo por idioma usa
`generateImageMetadata`, que também recebe `params`. Se isso complicar a URL da
imagem ou o build estático, o alt fica neutro (`Sinval Martins`) e a decisão é
registrada no commit.

**`sitemap.ts`:** duas entradas (`/pt-br` e `/en`), cada uma com
`alternates.languages` apontando para as duas.

**`manifest.ts`:** um arquivo só. `name` e `short_name` ficam neutros
(`Sinval Martins`), `start_url: "/"` (o proxy escolhe o idioma quando o app
abre).

**`robots.ts`:** não muda.

### Telas de erro

- **404** (`app/[lang]/not-found.tsx`): server component, lê o dicionário. O
  título da aba vai por um `<title>` dentro do componente (o React 19 leva para
  o `<head>`), igual ao que o `global-error.tsx` já faz. Motivo: o
  `not-found.tsx` não recebe `params`, e `generateMetadata` só é documentado
  para o `global-not-found`. Se na implementação `generateMetadata` funcionar
  no `not-found.tsx`, preferir ele.
- **Erro** (`app/[lang]/error.tsx`): precisa ser client component e não recebe
  props do servidor. O idioma vem do caminho.
- **Erro global** (`app/global-error.tsx`): fica fora de `[lang]` e desenha o
  próprio `<html>`. O idioma vem do caminho, e o `<html lang>` também.

Para os dois erros:

- `src/i18n/use-path-locale.ts`: hook client
  `usePathLocale(): Locale` = `pathLocale(usePathname()) ?? defaultLocale`.
- `src/i18n/error-texts.ts`: `{ "pt-br": { code, title, description, retry, back }, en: { … } }`.
  É o único texto que vai para o JavaScript do navegador, porque o error
  boundary roda no cliente. Fica num arquivo separado para não arrastar os
  dicionários inteiros junto.

## 3. Painel de preferências e troca sem intro

### Arquivos

```
src/components/preferences/
├── preferences-menu.tsx   # server: botão + painel; lê o dicionário
└── language-switch.tsx    # client: "Português" / "English"
src/components/intro/
└── intro-played.ts        # guarda se a intro já tocou nesta aba
```

### Botão e painel

- Botão na navbar, depois dos links, com ícone de ajustes (SVG inline,
  `aria-hidden`) e `aria-label` do dicionário ("Preferências" / "Preferences").
  Área de toque mínima de 44px.
- Entra na intro junto com os links. O `data-intro={INTRO.nav}` sai do `<nav>`
  e vai para um `<div>` novo que envolve o `<nav>` e o botão. O `<nav>`
  continua só com os links, porque o botão não é navegação.
- O painel fica dentro desse `<div>`, que a intro move com `transform`. Isso não
  desloca o painel: um `popover` aberto vai para a *top layer* e é posicionado
  em relação à janela, não aos ancestrais.
- Painel com o atributo `popover` e botão com `popoverTarget`. O navegador cuida
  de abrir, fechar com Esc, fechar clicando fora e devolver o foco ao botão.
  Não precisa de JavaScript para abrir e fechar, então o `preferences-menu.tsx`
  é server component.
- Posição: `position: fixed`, canto superior direito, logo abaixo da navbar
  (o botão está sempre ali, então não precisa de anchor positioning).
- Abrir e fechar: fade curto em CSS (`transition` + `@starting-style` +
  `transition-behavior: allow-discrete`). Com "reduzir movimento", sem
  transição.
- Conteúdo agora: título "Idioma" / "Language" e o `<LanguageSwitch />`. O
  subprojeto 2 acrescenta o grupo "Tema" aqui.
- Cores e estilo usam os tokens que já existem (`ink-800`, `line`, `fg`,
  `fg-muted`, `accent`).

### Navbar em telas estreitas

Medido hoje (logo + 3 links): sobram **7px** em 320px, **61px** em 375px e
**100px** em 414px. O botão precisa de 44px.

- Em 375px ou mais, cabe sem mudança.
- Abaixo disso, reduzir o espaçamento horizontal dos links (e, se preciso, o
  tamanho da fonte) só nessa faixa, até caber em 320px sem estouro horizontal.
  Confirmar medindo com o agent-browser.

### Seletor de idioma (`language-switch.tsx`)

- Dois `<Link>` do Next, um por idioma, com o texto no próprio idioma
  (`localeInfo[x].name`), `lang` e `hrefLang`. O idioma atual tem
  `aria-current="true"`.
- `href` = `localizePath(pathname atual, idioma)`. Sendo link, funciona sem
  JavaScript (vira navegação normal, com intro).
- Com JavaScript, o clique:
  1. grava o cookie: `locale={idioma}; path=/; max-age=31536000; SameSite=Lax`;
  2. chama `markIntroPlayed()`;
  3. navega com `replace` e `scroll={false}`, mantendo a âncora atual
     (`location.hash`). `replace` para o botão voltar não virar uma
     alternância entre idiomas.
- Recebe do `preferences-menu.tsx` (server) o idioma atual; os nomes dos
  idiomas vêm de `localeInfo`.

### Troca sem intro

- `intro-played.ts`: uma variável no módulo com `hasIntroPlayed()` e
  `markIntroPlayed()`. Variáveis de módulo sobrevivem à navegação no cliente e
  zeram no F5.
- Marcada em dois momentos: quando a intro termina (`onComplete`) e quando
  alguém troca de idioma.
- Na `<Intro>`, dentro do `useGSAP`: se `hasIntroPlayed()`, a timeline é criada
  normalmente, liberada (`releaseIntro`) e levada ao fim com `tl.progress(1)`.
  - `useGSAP` roda antes da pintura, então o preloader não pisca.
  - `progress(1)` não suprime callbacks, então o `onComplete` dispara e a luz
    que segue o mouse liga.
  - Vale para as duas timelines (completa e "reduzir movimento").
- Se na troca o React **não** montar a `<Intro>` de novo, a intro simplesmente
  não roda de novo e nada disso é acionado. Confirmar no navegador qual dos
  dois acontece e registrar no código.

## 5. Testes e verificação

### Automatizados

`pnpm test` = `node --test "src/**/*.test.ts"` (Node 24 roda TypeScript direto;
nenhuma dependência nova).

`negotiate-locale.test.ts`:

- `pt-BR,pt;q=0.9` → `pt-br`
- `en-US,en;q=0.9` → `en`
- `pt-PT` → `pt-br`
- `de-DE,pt;q=0.5` → `pt-br`
- `de-DE,en;q=0.8,pt;q=0.5` → `en`
- `en;q=0.5,pt;q=0.9` → `pt-br` (vale o peso, não a posição)
- `de` → `en`
- cabeçalho vazio ou ausente → `en`
- cookie `pt-br` com `Accept-Language: en-US` → `pt-br`
- cookie inválido (`fr`) com `Accept-Language: pt-BR` → `pt-br`

`localize-path.test.ts`:

- `localizePath("/pt-br", "en")` → `/en`
- `localizePath("/pt-br/x", "en")` → `/en/x`
- `localizePath("/en", "pt-br")` → `/pt-br`
- `localizePath("/x", "en")` → `/en/x`
- `localizePath("/", "pt-br")` → `/pt-br`
- `localizePath("/english", "pt-br")` → `/pt-br/english` (prefixo parecido não conta como idioma)
- `pathLocale("/en/x")` → `en`; `pathLocale("/english")` → `undefined`; `pathLocale("/")` → `undefined`

A paridade entre os dicionários é garantida pelo TypeScript, sem teste.

### No navegador (agent-browser)

- `/` com `Accept-Language: pt-BR` → `/pt-br`; com `en-US` → `/en`; com `de` → `/en`.
- Com cookie `locale=pt-br` e `Accept-Language: en-US` → `/pt-br`.
- Trocar o idioma no painel: a intro não repete, a rolagem não muda, textos e
  `<html lang>` mudam, o cookie é gravado.
- O mesmo com "reduzir movimento" ligado.
- Painel: abre pelo botão, fecha com Esc e clicando fora, funciona só com o
  teclado (Tab, Enter, Esc) e o foco volta ao botão.
- Navbar sem estouro horizontal em 320px, 375px e desktop.
- `/en/xyz` e `/xyz` mostram o 404 no idioma certo.
- Intro completa continua igual ao que é hoje na primeira visita.
